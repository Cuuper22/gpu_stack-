The point is not to simulate a GPU cluster. The point is to make the hidden chain of dependencies visible.

  • Every output is treated as the visible tip of a dependency graph.
  • Scenario values are allowed, but the model keeps track of where they enter.
  • Equations, unit checks, provenance, and root inputs stay attached to the claim.
  • The long-term direction is recursive decomposition, from hyperscale economics down toward particle-scale constraints.

Power, land, cooling

Datacenter

The visible machine is a building, but the model treats it as a constraint bundle: grid interconnect, substations, cooling loops, water, occupancy, capex, operations, and uptime.

  • Inputs include power envelope, PUE, utilization, cooling load, and build cost.
  • Outputs feed cluster capacity, cost allocation, emissions, and schedule pressure.
  • Open work is marked as root debt instead of being hidden in prose.

Equation cone

One output can have hundreds of upstream assumptions.

For econ.cost.per_token, the local dependency cone currently reaches 704 upstream variables and 289 root inputs. The useful part is not the number itself. The useful part is that the tool can show what the number is standing on.

Try it

Use the command line as a microscope.

The package is still closer to a research instrument than a polished app. That is useful right now. You can ask it what exists, what is unresolved, and where a claim bottoms out. 

python -m gpu_stack.cli stats
python -m gpu_stack.cli inspect econ.cost.per_token --cone
python -m gpu_stack.cli root-debt --top 10
python -m gpu_stack.cli scenario-report docs/examples/scenario.example.yaml

Good for now

  • Teaching the stack without flattening it into vibes.
  • Auditing which numbers are constants, equations, measured values, or scenario inputs.
  • Tracing a claim from economics into infrastructure, performance, manufacturing, and physics.

Not finished yet

  • It is not a full digital twin of a datacenter.
  • It still contains many root inputs that deserve deeper decomposition.
  • The visual language is early. The long-term target is closer to a living explorable proof.

Direction

Where the page wants to go next.

1. Cone viewer

A browser view where any variable expands into dependencies, equations, references, unit checks, and unresolved root inputs.

2. Stack atlas

A visual atlas from campus power to accelerator kernels, with toggles that reveal what a number is made of.

3. Scenario lab

A way to change assumptions and watch costs, emissions, latency, manufacturing limits, and utilization move together.

4. Physical floor

A deeper chain that keeps pushing root inputs toward material properties, thermal limits, geometry, nuclei, and quarks where the model can justify that move.
